# Tracker publication correction

The review of b08461a3, 77003da5 and 873a66e1 identified acknowledged writes omitted from JSONL, split external-import ownership, partial file publication on failure, and import hashes certifying skipped references. The corrective owner is `cli/src/tracker-mutation.ts`; CLI/server mutations reconcile under a SQLite write transaction, publish both tracked files with a durable journal, then commit. SQLite uses synchronous=FULL. Recovery uses the committed sync hashes under the same writer lock. Ordinary filesystem readers can observe the two rename operations separately; publication is recoverable, not simultaneous filesystem visibility.

Anonymous feedback is stored on its target spec or issue. Issue-originated feedback stays on its source issue. Import rejects missing targets/endpoints and misplaced or duplicate feedback before applying content or recording hashes. Imports that renumber collisions do not certify the original snapshots. External imports fetch first and then persist spec, links, tags and comments together; batch import and external refresh use the same mutation owner.
